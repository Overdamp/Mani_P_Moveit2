ทฤษฎีและหลักการทำงานของ Shelf Action Server (
shelf_action_server.py
)
โปรแกรมนี้ทำหน้าที่เป็น Action Server ในระบบ ROS 2 เพื่อควบคุมแขนหุ่นยนต์ (Manipulator) ให้เคลื่อนที่ไปยังช่องเก็บของบนชั้นวาง (Shelf) โดยอ้างอิงตำแหน่งจาก AprilTag

1. หลักการพื้นฐาน (Core Concepts)
1.1 Coordinate Frames (ระบบพิกัด)
หัวใจสำคัญของโปรแกรมนี้คือการจัดการกับระบบพิกัด 3 ส่วนหลัก:

Base Frame (Base_link): จุดอ้างอิงที่ฐานของหุ่นยนต์ (0,0,0 ของหุ่นยนต์) เป็นพิกัดที่คงที่ (Fixed Frame)
Tag Frame (tag11): จุดอ้างอิงที่ตัว AprilTag ที่ติดอยู่บนชั้นวาง ตำแหน่งนี้จะเปลี่ยนไปตามที่กล้องมองเห็น
Target Frame: จุดเป้าหมายที่เราต้องการให้ปลายแขนหุ่นยนต์ (End Effector) ไปถึง (เช่น ช่องแถวที่ 2 คอลัมน์ที่ 2)
1.2 TF (Transform Library)
เนื่องจากหุ่นยนต์รู้จักแต่พิกัดเทียบกับตัวมันเอง (Base_link) แต่เรารู้ตำแหน่งเป้าหมายเทียบกับชั้นวาง (tag11) เราจึงต้องใช้ TF (Transform) เพื่อคำนวณแปลงพิกัด: $$ P_{base} = T_{base \to tag} \times P_{tag} $$

$P_{tag}$: พิกัดเป้าหมายเทียบกับ Tag (เรารู้ค่านี้จากการคำนวณ Row/Col)
$T_{base \to tag}$: ความสัมพันธ์ระหว่างฐานหุ่นยนต์กับ Tag (ได้จากระบบ Vision/TF Tree)
$P_{base}$: พิกัดเป้าหมายเทียบกับฐานหุ่นยนต์ (ค่าที่ต้องส่งให้ MoveIt)
1.3 Motion Planning (MoveIt 2)
การเคลื่อนที่ของแขนหุ่นยนต์ที่มีหลายข้อต่อ (Joints) เป็นเรื่องซับซ้อน เราใช้ MoveIt 2 มาช่วย:

Inverse Kinematics (IK): คำนวณว่าต้องหมุนแต่ละข้อต่อกี่องศา เพื่อให้ปลายแขนไปอยู่ที่พิกัด $(x,y,z)$ ที่ต้องการ
Collision Checking: ตรวจสอบว่าเส้นทางที่ขยับไปจะชนสิ่งกีดขวางหรือไม่
Planner (RRTConnect): อัลกอริทึมค้นหาเส้นทางจากจุดเริ่มต้นไปจุดหมาย
2. ขั้นตอนการทำงาน (Workflow)
โปรแกรมทำงานตามลำดับขั้นตอนดังนี้:

Step 1: รับคำสั่ง (Goal Request)
User ส่งคำสั่งมาว่าต้องการไปที่ row (แถว) และ col (คอลัมน์) ไหน
เช่น row: 2, col: 2
Step 2: คำนวณตำแหน่งสัมพัทธ์ (Relative Pose Calculation)
โปรแกรมคำนวณตำแหน่งเป้าหมาย เทียบกับ Tag (tag11)
ใช้สูตร:
$X_{tag} = \text{Column Offset}$ (ซ้าย/ขวา)
$Y_{tag} = -(\text{Row} - 1) \times \text{Spacing}$ (ล่าง/บน) สังเกตเครื่องหมายลบ เพื่อให้แถวล่างมีค่า Y ลดลง
$Z_{tag} = \text{Standoff Distance}$ (ระยะห่างออกมาจากป้าย)
Step 3: แปลงพิกัด (Coordinate Transformation)
โปรแกรมถาม TF Buffer ว่า "ตอนนี้ Tag อยู่ตรงไหนเทียบกับ Base_link?"
นำตำแหน่งสัมพัทธ์จาก Step 2 มาแปลงเป็นตำแหน่งสัมบูรณ์ (Absolute Pose) เทียบกับ Base_link
ผลลัพธ์คือพิกัด $(x,y,z)$ และการหมุน $(qx,qy,qz,qw)$ ที่หุ่นยนต์ต้องไป
Step 4: สั่งการเคลื่อนที่ (Execution)
ส่งพิกัด Base_link ที่ได้ไปยัง MoveGroup Action Server
กำหนด Constraints (ข้อจำกัด):
Position Constraint: ต้องไปให้ถึงจุด $(x,y,z)$ ในระยะที่กำหนด (เช่น บวกลบ 5cm)
Orientation Constraint: (ถ้าเปิดใช้งาน) ต้องรักษาระดับหัวจับให้ขนานกับพื้น หรือหันไปทางทิศที่กำหนด
MoveIt วางแผนเส้นทาง (Plan) และสั่งมอเตอร์ให้ขยับ (Execute)
3. โครงสร้างโค้ด (Code Structure)
ShelfActionServer
 (Class): ตัวหลักของโปรแกรม
execute_callback
: ฟังก์ชันหลักที่ทำงานเมื่อได้รับคำสั่ง
get_target_pose
: ฟังก์ชันคำนวณและแปลงพิกัด (Step 2 & 3)
move_to_pose
: ฟังก์ชันส่งคำสั่งไป MoveIt (Step 4)
tf_buffer & tf_listener: ตัวดักฟังข้อมูลตำแหน่งสัมพันธ์ของเฟรมต่างๆ ในระบบ
4. สรุป (Summary)
โปรแกรมนี้คือ "ล่าม" ที่แปลความต้องการของมนุษย์ ("ไปช่อง 2,2") ให้เป็นภาษาที่หุ่นยนต์เข้าใจ ("ขยับข้อต่อ 1 ไป 30 องศา, ข้อต่อ 2 ไป 45 องศา...") โดยใช้คณิตศาสตร์เรื่องเมทริกซ์การแปลงพิกัด (Transformation Matrix) และอัลกอริทึมการวางแผนการเคลื่อนที่ (Motion Planning) ครับ
