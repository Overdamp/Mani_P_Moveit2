# ทฤษฎีและหลักการทำงานของ Adjust Level Action Server (`adjust_level_action_server.py`)

โปรแกรมนี้ทำหน้าที่ปรับ **"ทิศทาง" (Orientation)** ของปลายแขนหุ่นยนต์ให้ขนานหรือตรงกับเฟรมอ้างอิง (เช่น กล้อง ZED) โดยที่ **"ตำแหน่ง" (Position X, Y, Z)** ยังคงอยู่ที่เดิม ไม่ขยับไปไหน

## 1. หลักการพื้นฐาน (Core Concepts)

### 1.1 Decoupled Motion (การแยกการเคลื่อนที่)
ในบางสถานการณ์ เราต้องการหมุนแค่ข้อมือหรือปรับองศาหัวจับ โดยไม่ต้องการให้ตำแหน่ง $(x,y,z)$ ของหัวจับเปลี่ยนไป โปรแกรมนี้จึงแยกการควบคุมออกเป็น 2 ส่วน:
*   **Position**: ล็อกไว้ที่ค่าปัจจุบัน (Current Pose)
*   **Orientation**: รับค่ามาจากเป้าหมาย (Target Frame)

### 1.2 Cartesian Path Planning
เนื่องจากการหมุนตัวอยู่กับที่อาจทำให้แขนหุ่นยนต์ต้องขยับข้อต่อหลายส่วนพร้อมกัน (เพื่อชดเชยระยะ) เราจึงใช้ **Cartesian Path** ในการวางแผน:
*   เป็นการคำนวณเส้นทางแบบเส้นตรง (Linear Interpolation) ใน Cartesian Space
*   ช่วยให้มั่นใจว่าปลายแขนจะค่อยๆ หมุนปรับระดับโดยไม่เหวี่ยงไปมาแบบไร้ทิศทาง

## 2. ขั้นตอนการทำงาน (Workflow)

### Step 1: อ่านค่าปัจจุบัน (Get Current Pose)
*   โปรแกรมจะอ่านค่าพิกัดปัจจุบันของปลายแขน (`tcp_link`) เทียบกับฐาน (`Base_link`)
*   เก็บค่า $x, y, z$ ไว้

### Step 2: อ่านค่าเป้าหมาย (Get Target Orientation)
*   โปรแกรมจะอ่านค่าการหมุน (Rotation) ของเฟรมเป้าหมาย (เช่น `zed_left_camera_optical_frame`)
*   เก็บค่า Quaternion $(qx, qy, qz, qw)$ ไว้

### Step 3: ผสมพิกัด (Combine Pose)
*   สร้างเป้าหมายใหม่โดยใช้:
    *   Position: จาก Step 1 (ที่เดิม)
    *   Orientation: จาก Step 2 (ทิศทางใหม่)

### Step 4: วางแผนและสั่งการ (Compute & Execute)
*   ส่งเป้าหมายใหม่ไปให้ MoveIt คำนวณ **Cartesian Path**
*   MoveIt จะพยายามหาทางขยับข้อต่อเพื่อให้ปลายแขนหมุนไปหาทิศทางใหม่ โดยรักษาตำแหน่งเดิมไว้ให้มากที่สุด
*   หากทำได้ จะสั่งให้หุ่นยนต์เคลื่อนที่

## 3. ประโยชน์การใช้งาน (Use Cases)
*   **Camera Alignment**: ปรับหัวจับให้ขนานกับกล้อง เพื่อให้ Vision Algorithm ทำงานง่ายขึ้น
*   **Leveling**: ปรับหัวจับให้ขนานกับพื้นโลก (Gravity Align) เพื่อป้องกันของตก
*   **Fine Tuning**: ปรับแก้ทิศทางเล็กน้อยก่อนทำการหยิบจับ (Grasping)
